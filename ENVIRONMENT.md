# Environment configuration

Repository: https://github.com/nodelock/renewal-radar

Renewal Radar keeps secrets outside the repository. Use Vercel, Netlify, or a local `.env.local` file that is excluded by `.gitignore`. Never commit real values.

## Required server variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Neon or Supabase PostgreSQL connection string, preferably with SSL enabled |
| `GITHUB_CLIENT_ID` | GitHub OAuth App client ID used by the server-side token exchange |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth App secret; server-only and never exposed to the browser |
| `TELEGRAM_BOT_TOKEN` | Telegram Bot API token |
| `TELEGRAM_CHAT_ID` | Telegram destination chat ID |
| `SESSION_SECRET` | Random signing key for HttpOnly session cookies |
| `SCHEDULED_TASK_SECRET` | Secret for non-Vercel callers of the expiry scanner |

## Required browser variables

`VITE_GITHUB_CLIENT_ID` is the public GitHub OAuth client ID used to build the authorization URL. It is not a client secret. `VITE_REPO_URL` controls the public GitHub repository link and should be set to:

```text
https://github.com/nodelock/renewal-radar
```

Only variables intentionally used by browser code should use the `VITE_` prefix. Never prefix database credentials, session secrets, Telegram tokens, or `GITHUB_CLIENT_SECRET` with `VITE_`.

## GitHub OAuth callback

For the current Vercel deployment, configure the GitHub OAuth App with:

```text
Homepage URL:
https://renewal-radar-three.vercel.app

Authorization callback URL:
https://renewal-radar-three.vercel.app/api/oauth/callback
```

The callback URL must match the value generated by the browser exactly, including scheme, hostname, path, and trailing slash behavior.

## Local development

Use a separate GitHub OAuth App for local development and set its callback URL to:

```text
http://localhost:3000/api/oauth/callback
```

Use a separate development database and Telegram chat whenever possible. Production and preview environments should not share credentials or user data.
